# The GMH Figma files

Read this before any Figma work in this repo.

There is no Figma → code token pipeline any more. The MonoFly ingestion
(`script:tokens`, the Figma plugin, `tokens.json`/`styles.json`, the
`theme.css` drift report) was deleted on 2026-10-24 with the `--mfy-*` layer:
it read the MonoFly DSP file and emitted `--mfy-*`. Code is the source of
truth; Figma is built *from* the tokens.

## The libraries and the app

Publish order matters: a change reaches a consumer only after each library above it is republished (Foundations → UI → Blocks → App), and existing instances may still point at an old version after "accepting" an update — verify a bound variable inside the instance rather than trusting the update.

- **`T2yNPFTsBIX0iiOjDUdWe2` ("GMH - Foundations")**, built 2026-10-28 from `packages/tokens` in the GMH Lab Figma account (globalmh@gwu.edu), is **the** foundations library, the first of three libraries (Foundations → UI → Blocks), which GMH - App consumes. It is the single `--gmh-*` layer: 365 variables in eight collections — `Palette` (the 8 M3 tonal palettes, no scopes), `Color` (Light/Dark: the 49 M3 roles, success/warning/info, the brand-band roles, `navy`, plus `utility/focus-ring` and `utility/heading` from `globals.css`, and `utility/logo-ink` from ui's `logo.css` — primary in Light, on-surface in Dark — which the logo's and crest's Navy colourway ink is bound to, so the marks turn white in dark mode as on the site; `brand/navy` there was a bug fixed 2026-10-29), `Typography`, `Shape`, `Size` (space, stroke, icon, blur, layout widths), `State`, `Motion` and `Responsive` (Mobile/Tablet/Desktop). Colour variables are grouped by family for the picker (`primary/on-primary-container`); the CSS name is always the WEB code syntax. A role aliases a palette tone only where `color.css` says it is one; export values and GW pins stay literal. It has 16 text styles bound to the Typography variables (web faces only — Libre Baskerville / Nunito Sans / Roboto Mono, since the MCP has no Baskerville or Avenir Next), 5 `Elevation/Level` effect styles, the `GMH Logo` (Drawing × Colorway) and `GMH Crest` (Colorway) component sets with role-named layers bound to variables, and a documentation page per foundation. State opacities are 0–100 in Figma (0–1 in CSS).
- **`yg44sVQDqQwypKkrBIATMx` ("GMH - UI")** is the `@gmhlab/ui` component library, subscribed to Foundations (every colour, radius and gap is a Foundations variable). Phase 1 (2026-10-28) covers the icon set, Button, Icon Button, Badge, Input, Textarea, Checkbox, Radio, Switch, Avatar, Label, Separator, Kbd and Field, each with a docs panel. Phase 2 (also 2026-10-28) adds Select, Dropdown menu + Menubar (one shared `Menu item`), Popover, Dialog, Navigation menu, Accordion, Slider, Calendar, Button group and Input group, plus `Icon/ChevronLeft` (lucide, for Calendar — `@gmhlab/ui` has no such icon). Overlay surfaces are popover + a 10% on-surface `Ring` layer, with Elevation/Level 1–3 standing in for Tailwind's stock `shadow`/`shadow-md`/`shadow-lg`. A component-set TEXT property shares one default across variants, so a set whose variants need different copy (Dialog's Default/Destructive) has no text property. Phase 3 (also 2026-10-28) adds Text (one variant per role), Eyebrow, Blockquote, Text content heading/title, Image (incl. duotone, on a GW campus photo), Section (all six variants) and Flex & grid, plus local `Component/Eyebrow`, `Component/Blockquote` and `Component/Emphasis` text styles. Binding a gradient stop to a variable forces its alpha to 1, so the brand band's gold bloom and navy fall are bound solid fills under neutral gradient masks. Phase 4 (also 2026-10-28) adds the graphics kit, Card + StatsCard, Header + UtilityBar, Footer + NewsletterSignup, and Hero / Panel / CardGrid; the logo and crest are instances from Foundations. The kit's artwork was **rendered from `src/graphics` with `react-dom/server`, not redrawn**: each `var(--graphic-*)` role became a unique placeholder hex, `<pattern>`s and nested `<svg>`s were expanded (Figma's SVG import drops the first and turns the second into white-filled frames), and after `upload_assets` every placeholder was re-bound to its Foundations variable, in a Paper and a Brand variant. Derived tints in gradients stay literal. PathwayRule and PhotoBackdrop are CSS, so they were drawn by hand. The Pricing/Product/Review/Testimonial cards and FormBox are not drawn (MonoFly leftovers only the docs gallery uses). The UI library is complete. Translucent fills are separate layers with layer opacity, because Figma drops a paint's own opacity once its colour is bound to a variable.
- **`Ah2skPvpirQ74jeM03VuMR` ("GMH - Blocks")**, built 2026-10-29, is the `@gmhlab/blocks` library and the third of the three, subscribed to Foundations and UI. It is assembled from UI instances (Button, Badge, Input, Stats card, Research glyph, Contour globe, Care rings, Figure band, Wave divider, Photo backdrop, GMH Logo) and binds every colour, radius and gap to a Foundations variable. Pages: Cover, Getting started, `Page hero & CTA` (the shared PageHero with Globe/Contours/Rings motifs, PageCtaSection with Paper/Neutral/Brand grounds, Breadcrumb, Section heading), then Home, Projects, Project detail, Publications, Innovations, Innovation detail, Team, Contact and Slides. Each page has the 480px docs panel at x=-560, the block's section components, and **one composed example page at x=1760, built only from instances and fed the `apps/docs` synthetic corpus** (the Halden Centre, HARBOUR, ATLAS). It holds no GW content. The duotone is a desaturated image under two layers, `tertiary-container` set to MULTIPLY and `navy` set to LIGHTEN, because a variable-bound paint also drops its own blend mode. Home's photos are the docs fixture's picsum seeds. Home also has `Home approach item` / `Home approach band` (HomePage's optional `approach` section), which the docs demo does not exercise.
- **`ndCMczjpuWxI9h2AsmwfG3` ("GMH - App")**, started 2026-10-29, is `apps/web` drawn route by route. It subscribes to all three libraries and is **the only file that carries the GW Center's real content**. It has a Cover and a Getting started page in the libraries' template, then a Site map (the route tree with a status badge per route), then `Site shell` (layout.tsx: desktop shell, the header's active-route states, mobile chrome), then one page per route named by URL path (`/ · Home` … `/contact · Contact`). Each route page has the docs panel at x=-560 and a 1440 Desktop frame: real UI chrome (Utility bar, Header · lockup, Footer) around `main.site-main`, whose sections are **placeholders at the heights measured from the running app**, each naming the GMH - Blocks component it becomes. The plan is to build one route at a time by replacing placeholders with Blocks instances fed from `apps/web/src/content`, then flipping its Site map badge. Things to know: the UI Header and Utility bar are drawn at 1264, so at 1440 they get a 120px side inset; the UI Footer is 528px against the live 502px, so frames run 26px tall. `/` is built (2026-10-29): every section is a Blocks instance fed `HOME_CONTENT`'s real values, with Professors Gate under the hero and the `/about` photos in the approach band. That band needed a new Blocks component (`Home approach item` + `Home approach band`) — a Blocks change reaches this file only after the library is republished.

## Dark mode is where Figma drifts from code

Check Dark, not just Light — render a frame with the Color collection set to Dark beside the live site in dark mode. Three causes were found on GMH - App's home page (2026-10-29), all invisible in light mode because light `primary` is pinned to GW navy:
1. *CSS remaps a role by context; a Figma binding can't.* `logo.css` and `graphics.css` switch ink after `.dark` (logo → `on-surface`, graphics → `on-surface-variant`) and inside brand bands (→ `on-brand-band`). Foundations carries each paper-side role as a mode-switching variable — `utility/logo-ink`, `utility/graphic-ink` — and the kit's Paper variants bind to those, never to `primary` (M3's dark `primary` is a light blue for controls). Brand variants bind `on-brand-band` directly. A literal colour in a graphic (the hero's clearing was `#F7F9FF`) is the same bug: it must be a bound ground colour under an alpha mask.
2. *A brand band is three layers, not a fill.* `section.css` paints `brand-band` + a 30% gold bloom from the top-left + a fall into `palette-primary10`; the home CTA is `palette-primary15` with its bloom from the bottom-right; the focus-card art has its own 28% bloom. GMH - Blocks' **`Brand band ground`** (Kind = Band / Closing / Panel, optional contours) reproduces them with bound fills at layer opacity under alpha-gradient masks — make it the first, absolute child of every brand section rather than filling the frame.
3. *Graphics and stats cards are transparent in code.* The kit's `Ground=Brand` variants and `Stats card` used to paint a `brand-band` box, which only disappears on a flat band of the exact same colour.

Every variable's WEB code syntax is its CSS name **as of 2026-10-19 — `--md-*`/`--mfy-*`, which no longer exist.** The file predates the 2026-10-24 single-layer `--gmh-*` change: `Scheme`'s code syntax needs `--md-sys-color-` → `--gmh-color-`, the custom/brand-band roles need adding, and the `Color` collection is obsolete. Where code computes a colour (`color-mix` hovers, disabled alphas), Figma stores the resolved value and the formula sits in the variable description, so **re-resolve those when the tokens change**; nothing syncs them.

**`get_metadata` with no `nodeId` is misleading here**: it returns only `Cover` and `Logo` for *either* key, because it reports the currently-open desktop file rather than the key you passed. Query a concrete node id, or use `search_design_system` to locate a component.

## Figma write gotcha: `clone()` drops `componentPropertyReferences`

Cloning a variant to add a new one to a component set silently loses the children's property wiring, so the set's TEXT/BOOLEAN properties accept values that never render. After `clone()` + `appendChild`, re-set them explicitly on the children (`txt.componentPropertyReferences = { characters: "Text#…" }`). Verify by reading them back, not by looking at `componentProperties` on an instance — that reports the value correctly either way.
