# The GMH Figma files

Read this before any Figma work in this repo.

There is no automated Figma → code token pipeline. The MonoFly ingestion
(`script:tokens`, its plugin, `tokens.json`/`styles.json`, the `theme.css`
drift report) was deleted on 2026-10-24 with the `--mfy-*` layer it emitted.
Neither side is automatically authoritative: the Foundations file was first
built *from* the tokens, but a change can start in either place.

To get a file's tokens out by hand, two read-only development plugins
(Plugins → Development → Import plugin from manifest…) show copy-and-paste
text in JSON (lossless) or CSS:

- **`packages/tokens/scripts/figma-copy-variables/`** — every local
  collection, every mode, aliases by name. CSS names come from each
  variable's WEB code syntax, so the output lines up with `--gmh-*`.
- **`packages/tokens/scripts/figma-copy-styles/`** — paint, text, effect and
  grid styles, with bound variables written as `var(--…)`.

`ui.html` is the same file in both; edit both. Each folder also holds its
Figma listing art (`icon.png` 128×128, `thumbnail.png` 1920×1080), rendered
by `packages/tokens/scripts/figma-plugin-art/render.sh` from `art.html` with
headless Chrome. It needs a built `@gmhlab/tokens`, because the colours come
from the tokens CSS. Re-render the art; don't edit the PNGs.

**`packages/tokens/plugin-export/`** holds the plugins' output from GMH -
Foundations (`variables.{json,css}`, `styles.{json,css}`), pasted by hand as
a snapshot so a diff shows what changed in Figma between exports. Nothing
builds from them. To update, re-run the plugins and overwrite the files;
don't edit them.

Their playground file is **`VxtQb7XJJUrasKqRtmnjqy` ("GMH Copy Plugins —
Playground")**, built 2026-11-17 for the Figma listing. It is a small
stand-in, not a library: 46 variables in six collections (Palette, Color
Light/Dark with alias-of-alias chains, Typography, Shape, Size, State), with
GMH values and Web code syntax, plus 14 styles (5 paint, 4 text, 3 effect, 2
grid) bound to them, and one page with run instructions and a sample card in
Light and Dark. Binding a variable to a paint resets that paint's opacity, so
set opacity *after* `setBoundVariableForPaint`; `Scrim/Navy 40` needed exactly
that fix.

## The libraries and the app

All five files live in the GMH Lab team's **GMH Library** folder:
<https://www.figma.com/files/folder/692578747>. New GMH Figma files go there too.

Publish order matters: a change reaches a consumer only after each library above it is republished (Foundations → UI → Blocks → Apps / Dashboard), and existing instances may still point at an old version after "accepting" an update — verify a bound variable inside the instance rather than trusting the update.

- **`T2yNPFTsBIX0iiOjDUdWe2` ("GMH - Foundations")** ([open](https://www.figma.com/design/T2yNPFTsBIX0iiOjDUdWe2/GMH---Foundations)), built 2026-10-28 from `packages/tokens` in the GMH Lab Figma account (globalmh@gwu.edu), is **the** foundations library, the first of three libraries (Foundations → UI → Blocks), which GMH - Apps and GMH - Dashboard consume. It is the single `--gmh-*` layer: 365 variables in eight collections — `Palette` (the 8 M3 tonal palettes, no scopes), `Color` (Light/Dark: the 49 M3 roles, success/warning/info, the brand-band roles, `navy`, plus `utility/focus-ring` and `utility/heading` from `globals.css`, and `utility/logo-ink` from ui's `logo.css` — primary in Light, on-surface in Dark — which the logo's and crest's Navy colourway ink is bound to, so the marks turn white in dark mode as on the site; `brand/navy` there was a bug fixed 2026-10-29), `Typography`, `Shape`, `Size` (space, stroke, icon, blur, layout widths), `State`, `Motion` and `Responsive` (Mobile/Tablet/Desktop). Colour variables are grouped by family for the picker (`primary/on-primary-container`); the CSS name is always the WEB code syntax. A role aliases a palette tone only where `color.css` says it is one; export values and GW pins stay literal. It has 16 text styles bound to the Typography variables (web faces only — Libre Baskerville / Nunito Sans / Roboto Mono, since the MCP has no Baskerville or Avenir Next), 5 `Elevation/Level` effect styles, the `GMH Logo` (Drawing × Colorway) and `GMH Crest` (Colorway) component sets (`GMH Logo` stands for both ui's `GmhLogo` and its decorative `GmhMark` — same artwork, different behaviour in code, so there is no separate GMH Mark component anywhere; its description says which to use) with role-named layers bound to variables, and a documentation page per foundation. State opacities are 0–100 in Figma (0–1 in CSS).

Phase 2 (also 2026-10-28) adds Select, Dropdown menu + Menubar (one shared `Menu item`), Popover, Dialog, Navigation menu, Accordion, Slider, Calendar, Button group and Input group, plus `Icon/ChevronLeft` (lucide, for Calendar — `@gmhlab/ui` has no such icon). Overlay surfaces are popover + a 10% on-surface `Ring` layer, with Elevation/Level 1–3 standing in for Tailwind's stock `shadow`/`shadow-md`/`shadow-lg`. A component-set TEXT property shares one default across variants, so a set whose variants need different copy (Dialog's Default/Destructive) has no text property. Phase 3 (also 2026-10-28) adds Text (one variant per role), Eyebrow, Blockquote, Text content heading/title, Image (incl. duotone, on a GW campus photo), Section (all six variants) and Flex & grid, plus local `Component/Eyebrow`, `Component/Blockquote` and `Component/Emphasis` text styles. ## Dark mode is where Figma drifts from code

Check Dark, not just Light — render a frame with the Color collection set to Dark beside the live site in dark mode. Three causes were found on GMH - Apps' home page (2026-10-29), all invisible in light mode because light `primary` is pinned to GW navy:
1. *CSS remaps a role by context; a Figma binding can't.* `logo.css` and `graphics.css` switch ink after `.dark` (logo → `on-surface`, graphics → `on-surface-variant`) and inside brand bands (→ `on-brand-band`). Foundations carries each paper-side role as a mode-switching variable — `utility/logo-ink`, `utility/graphic-ink` — and the kit's Paper variants bind to those, never to `primary` (M3's dark `primary` is a light blue for controls). Brand variants bind `on-brand-band` directly. A literal colour in a graphic (the hero's clearing was `#F7F9FF`) is the same bug: it must be a bound ground colour under an alpha mask.
2. *A brand band is three layers, not a fill.* `section.css` paints `brand-band` + a 30% gold bloom from the top-left + a fall into `palette-primary10`; the home CTA is `palette-primary15` with its bloom from the bottom-right; the focus-card art has its own 28% bloom. GMH - Blocks' **`Brand band ground`** (Kind = Band / Closing / Panel, optional contours) reproduces them with bound fills at layer opacity under alpha-gradient masks — make it the first, absolute child of every brand section rather than filling the frame.
3. *Graphics and stats cards are transparent in code.* The kit's `Ground=Brand` variants and `Stats card` used to paint a `brand-band` box, which only disappears on a flat band of the exact same colour.

**`get_metadata` with no `nodeId` is misleading here**: it returns only `Cover` and `Logo` for *either* key, because it reports the currently-open desktop file rather than the key you passed. Query a concrete node id, or use `search_design_system` to locate a component.

## Figma write gotcha: `clone()` drops `componentPropertyReferences`

Cloning a variant to add a new one to a component set silently loses the children's property wiring, so the set's TEXT/BOOLEAN properties accept values that never render. After `clone()` + `appendChild`, re-set them explicitly on the children (`txt.componentPropertyReferences = { characters: "Text#…" }`). Verify by reading them back, not by looking at `componentProperties` on an instance — that reports the value correctly either way.
